# story-import：已有小说导入

把作者已发布的章节反向解析为 novel2all 项目结构，让作者从第 N+1 章无缝续写。

## 工作流

1. **输入**：作者提供 txt / docx / 在线链接
2. **章节切分**：自动识别章节边界
3. **逐章提取**（调 chapter-extractor role 并行）：
   - 关键事件
   - 涉及角色
   - 设定变更
   - 伏笔埋/收
   - 时间推进
4. **聚合成续写 bible**：
   - `_tracking-state.json` 一次性补齐到当前章
   - `设定/角色/{name}.md` 完整档案
   - `设定/世界观/...` 设定卡
   - `大纲/细纲_第NNN章.md` 已发布章节细纲（反向生成）
   - `正文/第NNN章.md` 原文备份
5. **生成"作者记忆"**：
   - 已发表内容的事实
   - 读者已知 vs 作者真相
   - 现有伏笔的当前状态

## 关键产物

```
{project_root}/
├── _tracking-state.json          # 一次性补齐到已发布章节
├── 设定/
│   ├── 角色/{name}.md          # 完整角色档案
│   ├── 关系.md                  # 角色关系图
│   └── 世界观/
├── 大纲/
│   ├── 大纲.md
│   └── 细纲_第NNN章.md          # 已发布章节细纲（反向生成）
├── 正文/
│   └── 第NNN章.md              # 原文备份
└── 拆文库/
    └── {书名}/                  # 如果作者提供了对标书
```

## 续写起点

导入完成后，作者可以：
```
/story-long-write 写第21章
```
novel2all 通过 `_tracking-state.json` 自动加载所有已有信息，作者无需重新交代设定。

## 关键原则

- **原文一字不删**——`正文/第NNN章.md` 是原文备份
- **不要"修正"作者原文**——续写时也按作者的笔法
- **续写时优先服从已建立的人物**——不要因为 AI 偏好改变角色性格
- **保留作者的语言风格**——去 AI 味 skill 会尊重作者风格

## 调用示例

```
用户：/story-import ./my_novel.txt
novel2all：
  1. 读取 txt，自动识别章节
  2. 并行调 chapter-extractor 提取每章关键信息
  3. 聚合 → 写入项目结构
  4. 输出"项目已建立，可从第 N+1 章续写"
```
